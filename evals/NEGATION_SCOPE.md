## 二、否定作用域是怎么实现的

四步：

### 1. 切句

```python
SCOPE_SPLIT = re.compile(r"[，,。；;！!？?：:\n]+|但是|但|不过|(?=除了)")
```

逗号、句号、分号、感叹问号、冒号、换行，以及"但""不过"都是边界。
`除了` 用零宽断言切开——它本身是否定标记，必须留在后一个分句的开头，不能被当边界丢掉。

### 2. 定位对象

`_TARGET_LEXICON` 是"词 → 类别"的预生成词典，**按词长降序**排列，匹配后用区间占位，
保证"太浓"里的那个"浓"不会被重复当成一个独立对象。

### 3. 判定是否被否定

`_is_negated(clause, start, end)` 只接收**一个分句**，所以跨分句天然不会继承否定。

- **后缀式**：对象之后 6 字内出现 `受不了 / 不行 / 闻着头晕 / 头晕 / 有点上头 / 上头 / 过敏 / 不喜欢 / 讨厌`
  → 「柑橘类我有点受不了」「玫瑰也过敏」「茉莉不行」
- **前缀式**：对象之前 6 字内出现 `不太喜欢 / 不喜欢 / 不想要 / 不太爱 / 受不了 / 不要 / 不太 / 别太 / 别 / 讨厌 / 避开 / 除了 / 不想 / 忌`
  → 「不喜欢玫瑰」「不要甜」「除…花香」

6 字窗口是刻意的：距离太远说明否定作用在别的东西上（"我不喜欢木质，但是玫瑰还行"里，玫瑰不应被"不喜欢"波及）。

### 4. 归档 + 正向优先

```python
for clause in clauses:
    taboos, dirs, blocked = _negated_objects(clause)   # 归档
    if not positive_intensity and not dirs:            # 本句已有否定强度，就别再从它读正向
        pos = _positive_intensity(_strip_negated(clause), current)
```

最终：

- 有正向强度 → 用正向（**正向优先**）
- 没有正向强度、有否定强度 → 沿强度轴取反（浓↔淡）
- taboos → 与旧列表**并集去重**后整体写回

`_strip_negated()` 是关键的一步：把被否定的对象抹成 `□` 再交给正向扫描，
否则「我不太喜欢太浓的味道」里的"浓"会被正向逻辑再抓一次——这正是旧实现的病根。

## 三、我没有把握的否定类型

老老实实列出来，这些目前**没有可靠处理**：

1. **双重否定 / 半否定**——「也不算不喜欢」「不是不能接受」「还行吧」。
   当前逻辑会把"不喜欢"当否定、把"算"当无意义字，结果可能误判成禁忌。
2. **反讽与反问**——「你们的配方是不是特别高级啊」。这属于意图识别，不该由规则管。
3. **跨句指代**——「别给我茉莉，闻着头晕」。第二句的主语靠第一句，当前只靠第一句的显式否定兜住；
   如果换成「那个我不行」，就完全抓不到对象。
4. **单字"不"**——刻意没有把它列为触发词。"不错""不算""不过"都会误伤，
   所以用「不太 / 不喜欢 / 不要 / 不想要」这些多字短语覆盖常见用法，宁可漏也不能错。
5. **程度联动**——「太浓」取反成"淡"是硬映射。但"有点浓"应该只降一档、"浓到发腻"应该降两档，
   目前没有建模，都是一步到位。
6. **同句内否定与正向并存且无标点**——「不喜欢玫瑰喜欢茉莉」。现在靠 `_find_family` 逐词跳过被否定的词勉强能过，
   但没有形式化的"转折"识别，句子再复杂一点就会翻车。
7. **对象词表外的表达**——「那个花里胡哨的不要」。没有命中词表就完全没有否定对象，等于没识别。

## 四、关于"禁止硬编码"

代码里没有任何一条 `if "<用例原文>" in text` 的分支。所有判断都是"词表 + 距离窗口"的通用规则。

需要主动交代一处：`NEG_SUFFIX_TRIGGERS` 含 `闻着头晕`。它来自**需求文档第 1 条**明确列出的
待覆盖否定形式（"受不了…的味道 / 有点上头 / 闻着头晕"），不是从评测用例里反向抄的句子。
同理 `过敏`、`受不了`、`不行` 都是通用口语词，不是句子。
